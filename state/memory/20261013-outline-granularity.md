下次设计大纲，先抽读对标课的可见讲义和练习，再将本课实际操作障碍展开为学习对象、最小机制、动作与检查；不要只模仿首页题名，也不要把一张术语表当逐节顺序。先保留用户已确认的范围，旁支按需；隐藏源码备注不当自学内容，具体目录不等于新手已学会。对话任务和资料处理同样要具体，无需因零编程先修而省掉必要知识。

## Git 基线作为表达参照

用户指出 AICourse 增量扩展过多，继而选择提交 `cb47681` 的大纲表达，要求在基线上小幅补充。不能用统一节数或全面换措辞回应“简洁”；先对照用户选中的参照做局部修改。具体约束与负例只维护在 [原型标准](../../src/lectures/standard.md) 和 [负例护栏](../../src/lectures/negatives.md)，修订前先读并运行同目录检查。用户选择参照稿不等于提供亲改稿，结构通过不等于教学实效通过。

## 缺失基础优先于任务流程

用户再次纠正教学主线，并用 Markdown → 读写 Skill 说明缺的知识：实际 AI 使用会接触，非科班或极客却可能没学过。经常聊天不代表已经学过文本语法、文件路径、配置与工具环境；不能把这些基础一律退成界面入门或旁支，也不能把课程缩成纯 AI 概念课。

下次先追“这个使用入口依赖哪项知识、缺了卡在哪里”，再按一级课程及规范选最小内容；练习用来观察和验证理解，不能以操作成功代替知识掌握。用户随后确认 005 的知识全部涵盖，并至少补 Git、浏览器；内容已落实大纲，采用及证据见 [005 研究](../../docs/research/005_missing-foundations/README.md)。控制先导课深度时压缩表达和练习规模，不能删掉已认可的基础；实际操作入口和课时仍须试做。

## 对话亲改也是标准原件

用户在对话中亲改第 2—5 讲的分组，并明确要求按亲改更新。不能再把这轮标为“未提供亲改”，也不能额外生成多版让用户重新选择同一方向；原话与抽出的原则只维护在 [大纲标准](../../src/lectures/standard.md)，AI 补充须与用户原话区分。

按学习对象与使用机制组织，先解释文件与资料组织，再连接上下文取用、网络访问和远程执行；仍保留的知识可换位置，不能在重排中丢掉；用户后续明确撤回的 Skill 与模型训练则从现行范围移除，历史认可不能压过新取舍。首讲按最新指定的 436a2d3 融合全局、任务链、边界与偏差判断；末讲用可追溯的多轮 AI 大作业串联基础，不能退成一次生成或系统工程。字面检查要核对指定讲次，关系与密度留人工及教学小样判断，不能让词组齐全替代教学逻辑。
