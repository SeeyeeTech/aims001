用户指出初稿笼统、与 Missing Semester 风格不同。初稿已有主任务和判据，知识点也已在研究表中；问题在于把课程级能力路径直接当成了教学目录，没有展开读者能看到的节次与工作机制。核查及用户 AA 拍板记录见 `docs/research/002_outline-design/decision.md:25`；逐节正文已迁入 `src/lectures/outline.md`，后续只维护正本。

下次设计大纲，先抽读对标课的可见讲义和练习，再将本课实际操作障碍展开为学习对象、最小机制、动作与检查；不要只模仿首页题名，也不要把一张术语表当逐节顺序。先保留用户已确认的范围，旁支按需；隐藏源码备注不当自学内容，具体目录不等于新手已学会。对话任务和资料处理同样要具体，无需因零编程先修而省掉必要知识。

## Git 基线作为表达参照

用户指出 AICourse 增量扩展过多，继而选择提交 `cb47681` 的大纲表达，要求在基线上小幅补充。不能用统一节数或全面换措辞回应“简洁”；先对照用户选中的参照做局部修改。具体约束与负例只维护在 [原型标准](../../src/lectures/standard.md) 和 [负例护栏](../../src/lectures/negatives.md)，修订前先读并运行同目录检查。用户选择参照稿不等于提供亲改稿，结构通过不等于教学实效通过。

## 缺失基础优先于任务流程

用户再次纠正教学主线，并用 Markdown → 读写 Skill 说明缺的知识：实际 AI 使用会接触，非科班或极客却可能没学过。经常聊天不代表已经学过文本语法、文件路径、配置与工具环境；不能把这些基础一律退成界面入门或旁支，也不能把课程缩成纯 AI 概念课。

下次先追“这个使用入口依赖哪项知识、缺了卡在哪里”，再按一级课程及规范选最小内容；练习用来观察和验证理解，不能以操作成功代替知识掌握。此次候选与证据见 [005 研究](../../docs/research/005_missing-foundations/README.md)，选题是否采用仍以用户决定为准。
