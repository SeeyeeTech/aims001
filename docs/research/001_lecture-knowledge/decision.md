## 建议选什么

沿现有六讲嵌入三层内容：全体亲手做的主练习、遇到再查的认识卡、主题选修的深入操作。文件定位与类型、Markdown 最小编辑、版本恢复进入核心；OCR/ASR/翻译等先认识任务地图，再按材料或选修完整练习。第 6 讲只检验迁移。依据 O1—O4、S3—S13；具体分配是教学推断。

先做第 3 讲材料处理小样，验证文件定位、扫描材料识别、读取范围与来源定位。它最能暴露电脑基础和“AI 看到了什么”两个未知。

## 建议舍什么

完整格式语法、HTML/CSS/JS 开发、JSON/YAML 配置、Git 命令、Shell、API/MCP 配置和训练原理不列全体必修。用户选择第 5 讲增加 HTML 或 GUI Git 微练习；完整开发和 Git 深入操作仍放选修。依据 O1、S1、S3、S9。

已选方案：第 5 讲增加 GUI Git 或 HTML 微练习，替换部分复用练习；具体选哪一种留到小样测试，不认定两者都必做。先测负荷再定课时，不扩核心讲数。

## 两把尺子

复用：自有草案依结构细化；外部只借鉴事实与设计方法，自行编写，未复制课程或克隆代码。

满意：每讲有能力、操作、判据、依据，有反例验证，能列待拍板点。最优的“全格式、全产品、全媒体均实操”暂舍，避免挤掉练习与迁移。

支持依据：O1 的零先修与操作验收、S3 的文件前置能力。最不利依据：S1 把 Git/Shell 作为重要工具；但其 CS 受众不同，不能推出本课全体必修命令。

最大缺口：没有零基础试教证据。三个风险：课时负荷、设备/账号条件、课堂入口实际支持；对应按需卡片、课前操作冒烟、选型后试传。
