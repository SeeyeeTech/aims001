# 004 · 大纲与 AICourse 基本思想的符合性

**总体符合，作为先导课的范围合理；混合智能的共同框架与后续模块的概念衔接还需补强。** 当前大纲已覆盖任务、上下文、工具、人机分工、验证和复用，但 Harness 的职责、人的专业经验如何进入工作流、方法与执行能力的区别尚未明确。这是大纲表达的缺口，不能据此断言未来讲义不会教。

分析对象是[当前大纲](../../../src/lectures/outline.md)，课程关系见[现实约束](../../../.42cog/real.md)。判断以本项目[意向书](../../../.42cog/intent.md)为先：检查先导课是否建立同一套工作认识，并为后续学习准备前置知识。

核对基线：本项目提交 `8bc77b7930b430c41d80026d74fa36eb42d4057f`；AICourse 提交 `320a5ac38f8ac786effa60d2fba23c2fbc0e61eb`。本次引用的 AICourse 原文在核对时无未提交改动；行号随原件更新需重查，材料状态见[模块索引](../../../vault/truth/aicourse-reference.md)。

## 从原文提炼的判断依据

以下是对课程立场的归纳；右栏是本次分析判断，不是 AICourse 对本课作出的评价。

| AICourse 的基本思想与原文依据 | 当前大纲的证据 | 判断 |
|---|---|---|
| 用 AI 完成真实工作，形成可复用、可验证的工作流。[AI101 介绍](../../../vault/raw/AICourse/courses/ai101/README.md)：L5–9、L24–29、L78 | 大纲 L9 的完整任务链、L25 的多步流程、L29 的迁移与复用；意向书要求真实任务和修复成果 | 明确符合。纠偏服务于稳定完成任务，与上游的能力扩展能够衔接 |
| 将 LLM、Harness、Context、Human 放进同一协作系统。[全局讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson01/lecture.md)：L7–15 | 大纲 L9 已列模型、应用、工具、Agent 和人机分工 | 部分符合。要说明应用如何管理上下文、组织调用和反馈；仅列这些对象还不能保证学员看清它们的关系 |
| 有限上下文中接入真实工作材料；记忆与执行循环由宿主组织。[全局讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson01/lecture.md)：L68–70、L111–134 | 大纲 L17 的窗口、历史、外部记忆、取材、检索和版本 | 方向符合。样章仍需解释材料何时进入当前上下文，以及文件存在、上传成功和内容实际可用之间的关系 |
| 人的专业知识和工作经验可以封装为方法；价值取决于解决问题的效果。[Skill 讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson02/lecture.md)：L23–31、L108–141、L154–188 | 大纲 L13 的要求、示例与迭代，L21 的领域知识，L29 的可复用步骤 | 部分符合。三个位置已有基础，但尚未把领域经验、方法和质量判据连成一个可再次使用的工作说明 |
| 方法和工具能力共同构成工作流；连接协议不能凭空创造能力。[MCP 讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson04/lecture.md)：L17–32、L134–168 | 大纲 L9 区分生成和工具执行，L25 列工具调用、流程和失败反馈 | 部分符合。应让学员能区分缺方法、缺材料和缺执行能力，并观察调用、返回和下一步判断 |
| 人参与目标、权限、关键节点和验收；检查过程与成果。[AI101 介绍](../../../vault/raw/AICourse/courses/ai101/README.md)：L28、L47、L78；[MCP 讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson04/lecture.md)：L703–712 | 大纲 L21 的外部核验与过程检查、L25 的权限与恢复、L29 的按风险验收 | 明确符合。第 4 讲的核验有上游依据；后续实操应让检查支持任务推进，并保留失败、修复和恢复记录 |

## 建议优先补强的三处

1. **第 1 讲明确四要素及其关系。** 用通俗说明讲清：模型负责生成和选择，Harness 是组织上下文、工具执行与反馈的应用环境，Context 是当前可用信息，Human 提供目标、经验和判断。沿用已有任务链解释它们如何协作，把这个框架用于后续定位偏差。无需为此增加一讲。
2. **第 2、6 讲接上专业经验与方法复用。** 在已有目标、约束、示例、反馈和可复用步骤中，加入领域工作方法和质量判据；综合任务留下可再次使用的工作说明，包含输入、步骤、检查点、例外和适用边界。它为后续 Skill 学习准备内容基础，核心课不必制作或安装正式 Skill。
3. **第 5 讲显式区分方法与执行能力。** 在既定工具微练习中，观察一次真实调用及其结果反馈，说明哪一步依靠模型、哪一步需要外部工具、哪一步需要人的判断。把缺工具、未执行、返回错误与回答错误分别定位；保留已定的 HTML／GUI Git 二择一，具体路径仍经小样决定。

以上是修订建议，尚未替换大纲。第 3 讲的材料读取与版本案例可作为四要素框架的首次应用，第 4 讲继续检验事实、推断和过程，第 6 讲再用替换任务检验方法复用。六讲次序与已确认范围可以保留。

## 各模块如何衔接

下表给后续学习入口，概括各模块在原课程中的职责；模块名称不能代替先导课的实际练习。

| 后续 AI101 模块 | 本课应准备的基础 | 当前承接位置 |
|---|---|---|
| Skill：封装经验和方法 | 任务说明、领域经验、步骤、资源与质量判据 | 第 2、4、6 讲；专业方法与复用需要连贯表达 |
| MCP：接入数据和执行能力 | 知道工具依赖、读懂调用结果、判断材料与权限 | 第 3、5 讲；补清方法与能力的区别 |
| Hook：在关键事件触发动作 | 知道哪个节点需要检查、检查什么、失败如何处理 | 第 4、5 讲已有检查基础，事件配置留后续 |
| Agent：循环推进多步任务 | 目标、上下文、调用、反馈、调整与人工介入 | 第 1、5、6 讲已有基础，循环关系需显式说明 |
| Command：固定操作入口 | 把重复操作整理为有输入、步骤和判据的方法 | 第 6 讲的复用成果；具体入口机制留后续 |
| 人机关系与长程任务 | 责任、验收、状态、恢复与适用边界 | 第 4–6 讲提供基础，长期运行治理留上游课程 |

模块分工依据：[AI101 规划](../../../vault/raw/AICourse/courses/ai101/README.md)：L37–55；[Skill 讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson02/lecture.md)：L143–152；[MCP 讲义](../../../vault/raw/AICourse/courses/ai101/lessons/lesson04/lecture.md)：L17–32。Hook、Agent、Command 与未来展望的独立讲义尚未发现，不能把规划视为已走通的教学内容。

## 范围与验证边界

完整的 Skill 制作、MCP／Hook 配置、Agent 环境搭建和长程运行治理可以留给 AICourse。其系列进阶路径见[系列介绍](../../../vault/raw/AICourse/docs/guides/course-series-introduction.md)：L5–27；本课已有前置知识、工具和综合任务内容，不必按上游模块重排六讲。

原文中的具体产品推荐、历史日期、性能数字和配置细节不作为本次思想判断的依据。采用这些操作内容时再核验；上游也要求区分事实、建议和假设，并走通练习，见[现实约束](../../../vault/raw/AICourse/.42cog/real.md)：L4–7。

本轮按使用者、框架解释和失败路径三个视角串行自查：保留本课已定目标与范围；将“未明确”与“完全缺失”分开；将回答错误、材料问题和执行问题分开。结论限于文本符合性，没有目标学员试教证据。

后续可用第 3、5 讲小样检查承接：学员能否将失败定位到四要素和任务链，能否区分方法与工具问题，能否用替换材料再次完成任务。这些是待验证的问题，不是已通过的教学结果。
