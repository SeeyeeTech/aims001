# 课程大纲 · 负例护栏

范围仅限 [大纲](outline.md)；对应 [standard.md](standard.md) 的三条硬约束。

## 事后 · 从本轮退回的稿件抽取

用户先指出扩展过多、不像先导课，再明确选择 Git 基线的表达。将这两次反馈落为以下护栏，不靠重新写一版解决。

| 编号 | 负例 | 形态 |
|---|---|---|
| N1 | 为对齐上游增加核心讲次 | 脚本：仍为六讲 |
| N2 | 用新主题替换基线讲题与次序 | 脚本：与基线讲题对照 |
| N3 | 为压缩篇幅合并、删减、改名或重排小节 | 脚本：与基线小节名称及编号对照 |
| N4 | 在一句说明里塞入整段教学内容 | 脚本：每讲最多 200 字 |
| N5 | 在小节之外追加独立知识点或长解释 | 脚本：讲内仅允许既有格式的小节 |
| N6 | 残留模板占位，或直接承诺配置、封装和搭建能力 | 脚本：PATTERNS |
| N7 | 为统一措辞全面改写未涉及的说明 | Skill：人工核对差异 |
| N8 | 把知识与机制名称换成泛化行动口号 | Skill：人工核对表达 |
| N9 | 将研究的完整建议全部变成先导课目标 | Skill：人工核对范围 |

三条正向约束对应九条负例。结构护栏随 Git 参照检查；字面模式只查明确表述，不能替代范围判断。

## 事前 · 主动攻击

试着删掉一节、加一段长解释，或把对齐点改成系统搭建目标；检查必须失败。实际反例冒烟结果记入状态板，不把脚本通过当作教学效果。

## PATTERNS

每行是 Python 正则、一个 TAB 和说明；只扫描六讲正文。结构与字数由同目录 `check.sh` 检查。

```PATTERNS
\{\{[^}]*\}\}	未填写的模板占位
(?:掌握|实操|练习)\s*(?:Skill|MCP|Hook)\s*(?:封装|配置|部署)	提前加入完整封装或配置目标
(?:搭建|部署)\s*(?:完整\s*)?(?:Agent|智能体|AI\s*自主)\s*系统	提前加入系统搭建目标
```

## CHECKLIST

```CHECKLIST
对照基线差异，是否仅补了有证据的对齐点，未全面改写已有说明
是否仍为知识点名称加一句说明，而非泛化的行动口号
是否保持先导课范围，将完整封装、配置和系统搭建留给后续课程
```
