## 定位与组织方式

中文副标题建议：**补齐前置知识，把 AI 用好**。受众与课程方向以意向书为准。默认学员已有日常 AI 对话经验；编程、英文技术阅读或机器学习课程不设先修。课内补足能解释使用偏差的机制。

核心课 **6 讲**，首讲最小全局认识，末讲综合实践；主题选修**最多 4 讲**。课程采用工作坊形式，每讲有演示、亲手操作、反馈与修改。

已确认采用学习对象题名与逐节操作目录。节次按操作障碍和前置关系排列，写清知识、必要机制、学生动作和检查；一个名词如果不能解释错误或改变操作，就不占核心节次。“核心”是全体亲手完成，“认识”只辨用途与边界，“按需”是遇到障碍再查。每讲的节次串同一个主任务。

## 难度与前置知识

课前诊断要求学员带一件常用任务，说明一次失败及当时如何处理；提供匿名、无敏感信息的替代样例。已有操作熟练度只决定是否需要补救卡，不免除机制与核验练习。

核心任务从“按步骤做出来”提升到“定位偏差→说明机制→选择干预→对照验证→换材料复测”。下面的增补是本轮深度修订，仍需负荷定标：

| 讲次 | 必补前置知识与加难练习 | 完成证据 |
|---|---|---|
| 2 | 指令、材料、示例和验收约束的作用；在同一输入上逐次只改一项要求，比较任务说明、示例与局部反馈的效果，解释示例污染和事实漂移 | 保存基准及两次对照，写可观察的检查项，用替换题验证任务卡；不把一次成功推广成万能提示词 |
| 3 | 文件解析、上下文容量、取材与版本范围；从冲突材料中建立来源索引，分别测定位题、跨片段题和无答案题 | 原件到回答的依据链，遗漏诊断与修复记录；上传成功不计作读全 |
| 4 | 主张与证据、来源独立性、计算与错误传播；混入“真实链接但不支持主张”、过期条件和上游提取错误 | 解释证据为何支持或不支持，修复上游后复查下游，用新错误稿验证；AI 自报置信度不代替证据 |
| 5 | 数据表示、转换、流程依赖、版本差异与恢复；主动制造一次格式或修改失败，按检查点排障，完成既定 HTML／GUI Git 微练习 | 能解释故障层、恢复依据和交付条件；不只提交能打开的文件 |
| 6 | 将前五讲机制迁移到陌生任务；含冲突、缺失与一个可恢复失败，自行选择工具和核验强度 | 任务说明、诊断与干预记录、依据、可用交付物及适用边界；记录教师帮助，成品外观不代替独立完成 |

机制知识需要足以解释观察并改变操作；不增加无关术语或公式推导。第 1 讲保留全局认识，第 6 讲保留综合实践，多模态完整操作和 HTML／GUI Git 二择一沿用已确认范围。

## 共享材料与单讲学习

已确认前五讲共享一组事实材料，**各讲独立提供输入，配替换题**。暂以明确标注为虚构的“小型分享活动”为材料背景；具体通知、更新说明、错误稿及文件在样章阶段制作。

事实材料统一维护原件、日期、适用版本与索引；各讲领取包提供本讲所需原文、任务卡及必要中间产物。阅读某一讲时能够重新取得输入，不要求从上一讲的聊天历史找材料。材料名称和操作任务是设计要求，尚未冒称已有完整材料包。

每讲至少有一道更换材料的练习，检查能否迁移到工作、生活或学习中的类似任务。第 6 讲更换任务或资料，记录帮助程度，由实际使用者判断成果能否使用。

## 工作坊节奏与操作边界

90 分钟仅作负荷测试建议：10 分钟问题与必要概念 → 15 分钟演示 → 45 分钟实操 → 15 分钟互评修改 → 5 分钟整理方法。第 6 讲建议 10 分钟选题与验收说明 → 60 分钟制作 → 15 分钟展示反馈 → 5 分钟复盘。实际课时按第 3、5 讲小样逐节耗时、提示次数和卡点确定。

基础练习可两人协作，关键操作由每位学生完成；材料包、分步任务卡、提示和成果检查表在样章阶段配齐。固定回复可练检查，真实入口的操作能力仍须实际任务验证。

多模态在核心课识别用途，完整 OCR/ASR 等操作放选修。第 5 讲 HTML 或 GUI Git 微练习二择一，以小样落实，不认定两条路径都必做。首讲不讲训练原理、网络结构或产品排行榜；末讲不增加必修术语。

上传前检查资料分享权限，把原文里的指令与自己交代的任务分开；发布、购买、删除等动作保留人为决定。学生在成果与核验记录中说明这些判断。

## 第 1 讲 · 生成机制、能力边界与失败诊断

障碍：已有使用经验，却把生成、检索与执行混在一起，遇到偏差只能重复追问。主任务：诊断同一通知任务中的遗漏、编造与未执行，修复并解释依据。

| 节次 | 具体教什么与为什么 | 学生操作 |
|---|---|---|
| 1.1 日常使用偏差诊断 | 熟悉界面不等于理解任务链；先辨缺材料、误解要求、生成错误和工具失败 | 比较同一任务的三份错误结果，写失败假设和还缺的证据；记录自己的常见困惑 |
| 1.2 生成的最小机制 | token 是处理文本的单位；生成不是从事实库直接复制，语言流畅与事实可靠须分开检查；机制细节在样章中附核验来源 | 对比有原文与无原文的回答，标出可核查事实及无依据补全；重复任务，观察结果差异 |
| 1.3 应用、模型与工具 | 区分界面功能、模型生成与工具返回；模型自述不等于实际调用记录 | 把查日期、算总数、写通知和发送拆开，核查工具记录或外部结果，定位哪里需要执行证据 |
| 1.4 上下文与任务状态 | 当前材料、历史、记忆与工具返回各有来源和边界；“之前告诉过”不能代替可用性验证 | 原对话与新对话做对照，确认任务所需信息，重建最小材料包并复测 |
| 1.5 选择修复方法 | 补材料、改要求、换工具与人工核验对应不同问题 | 为三类错误各选修复方法，以新通知复测；解释为何单纯加角色或重复追问不足 |

核心成果：失败分类表、修复后的行动清单与对照记录。检查：能区分事实错误、材料缺失和未执行；用证据支持诊断，换通知仍可修复。登录、输入框等界面操作放课前补救卡。

## 第 2 讲 · 提示词、示例与多轮修改

障碍：想要的结果和收到的结果不一致，不会提出有效修改。主任务：用同一组事实写一份给指定对象的通知。

| 节次 | 具体教什么与为什么 | 学生操作 |
|---|---|---|
| 2.1 从愿望到任务说明 | 目标、对象、约束、完成标准；要求具体才有办法判好坏 | 比较“写个通知”与明确要求的两份结果，补上对象、长度、必含字段和缺失处理 |
| 2.2 分开要求与原材料 | 原文里的句子是资料，不能自动变成当前任务的指令 | 把自己的要求与通知原文分段标明；识别材料中一条不应照做的指令 |
| 2.3 示例和输出结构 | 给表头或短示例可以减少格式歧义；示例中的事实不能当新任务事实 | 给“事项／时间／负责人”的表头；用明确缺失的字段检查它是否照抄了示例 |
| 2.4 定位问题与局部修改 | 多轮修改需要说清哪段、哪里错、怎样改；正确内容也可能被改坏 | 只改对象和语气，保留日期、地点；比较修改前后，检查事实是否漂移 |
| 2.5 任务卡与适用范围 | 可复用的是可替换输入和检查，角色标签不能提供事实权威 | 保存任务说明卡；指出换材料时要替换哪些内容及重新查哪些字段 |

核心成果：任务卡、修订通知、修改说明。检查：满足事先写下的要求，事实没有因改写变化；能解释哪一次反馈解决了什么。Markdown 在这里仅认识标题、列表和源文／预览，亲手编辑放第 5 讲。

## 第 3 讲 · 文件、格式与上下文

障碍：文件交上去了，却不知道是否读对、读全、读到了最新资料。主任务：从一个含旧通知和更新说明的资料包生成带出处的 FAQ。

| 节次 | 具体教什么与为什么 | 学生操作 |
|---|---|---|
| 3.1 文件表示与读取链 | 文件内容、扩展名、编码、解析结果与界面预览不是同一层；定位和下载用补救卡 | 检查同名异版和改后缀样例，比较原文件、预览与提取文本，定位偏差发生在哪层 |
| 3.2 内容、格式与读取方式 | 改后缀不会转换内容；PDF 可以有文字、图像或混合内容，显示与解析有差别 | 用教师提供的文字／扫描对照观察能读取什么；识别需要 OCR 的情形，完整识别操作放选修；编码和格式大全按需查 |
| 3.3 材料进入上下文 | 输入、文件解析和检索等环节会影响实际可用内容；上传成功不能证明全部读到 | 清点文件；问一道只有更新说明才有答案的定位题，检查它是否引用了正确文件和位置 |
| 3.4 版本、来源与缺失 | 新旧资料有适用范围；不能只凭文件名或“更新”字样替代核验 | 对照日期和更新说明列适用版本；冲突若不能由材料解决，标待确认；找出没有收费信息的问题 |
| 3.5 上下文容量与重新提供 | 容量有限，历史、记忆、资料库不是同一种对象；超长材料处理是按需策略 | 在新对话核查资料是否仍可用；不在就重新提供；亲手选择相关片段，保留索引和出处；设计跨片段问题与无答案题，检验取材是否遗漏关键条件，不背 token 换算 |

核心成果：材料清单与 FAQ，答案能回到文件的页、段或行。检查：使用更新后的时间地点，不补编费用；资料内指令不覆盖自己的要求。最小任务走查见 [实验](../../docs/experiments/exp002-outline-task/readme.md)，它不证明学生已经会上传或已经读懂。

## 第 4 讲 · 搜索、证据与结果纠错

障碍：流畅的答案和看似真实的链接容易被当作依据。主任务：修订一份预先埋入错误的说明稿。

| 节次 | 具体教什么与为什么 | 学生操作 |
|---|---|---|
| 4.1 把结果拆成可核查主张 | 事实、推断、建议、未知需要不同判断方式 | 标出稿中的日期、数字、因果判断和建议，选择会影响交付的关键主张 |
| 4.2 搜索结果与原始来源 | 搜索或引用链接是入口；源头是否支持这句话、是否适用于当前日期才是证据 | 先用本地材料；需要外部信息时打开原始页面，检查正文和发布日期。现场网页不可用时用标注日期的材料快照 |
| 4.3 数字、单位与关键条件 | 计算与文字生成是不同环节；漏掉单位、否定或限制会改变结论 | 用计算器复算一项总数，回原文核对日期、专名与一条限制条件 |
| 4.4 修正和回归检查 | 第二个 AI 可帮挑错，但不能充当独立事实来源；修一处也要查连带变化 | 写“主张—出处—处理”记录，局部修订；再核对之前正确的字段 |
| 4.5 中间产物与错误传播 | 提取或识别出错后，摘要可能只是把错信息写得更顺 | 用教师提供的识别文本对照原页，定位上游错误；再修摘要，不要求核心课做完整 OCR/ASR |

核心成果：核验记录与修订稿。检查：关键主张有真正支持它的出处，数字能复算；没有依据的内容保留未知。结构和格式正确不能代替事实检查。

## 第 5 讲 · Markdown、文件交付与修改恢复

障碍：结果停在聊天框，下载后打不开，改坏了无法找回。主任务：把前几讲的核验内容交成一份接收者能打开的说明文件。

| 节次 | 具体教什么与为什么 | 学生操作 |
|---|---|---|
| 5.1 任务拆解、依赖与检查点 | 先核验内容再定稿；保存、预览、交付之间有依赖；失败要知道退到哪里 | 把主任务排成“确认内容→选格式→编辑→保存→重新打开→交付”，为每步写输入、输出和检查；若打不开，退到保存／格式环节，不重做已核验的内容 |
| 5.2 Markdown 与目标格式 | 标题、列表、链接让文本有结构；源文与预览、保存与转换有差别，接收者决定格式 | 编辑一个标题、一组清单和一条链接，核对源文及预览；根据接收者选目标格式；其余语法和格式种类用卡片 |
| 5.3 修改、保存与恢复：一条工具路径 | HTML 或 GUI Git 微练习二择一；版本记录帮助发现改坏的内容，不能代替独立备份 | 采用下方一条路径，建立明确检查点→改一处内容→看差异→恢复→再次核对；不另练第二套恢复流程 |
| 5.4 导出与交付检查 | 文件存在、能打开、显示正确、内容正确是不同检查 | 找到下载文件，用接收者的工具重新打开，检查标题、链接和关键字段；依据 5.1 的检查点处理失败，附换材料时需重做的步骤 |

5.3 的路径候选：

- **HTML**：教师提供一个不依赖外部资源的单文件 HTML；预装 VS Code 作为候选编辑器，使用 Timeline 的本地历史建立一个明确检查点，再保存为 `.html`、用浏览器打开、修改给定日期、比较差异并恢复选中记录。历史记录可比较和恢复的官方依据见[来源登记的 R8](../../docs/research/002_outline-design/sources.md)；样章前须核验课堂版本、记录设置和设备，不能默认每台机器已有此环境。不要求写 HTML/CSS/JS 或安装扩展。
- **GUI Git**：教师提供已就绪的本地仓库及图形客户端，学生提交基准、修改同一处内容、看差异、恢复该处并复查；替代 HTML 与编辑器历史环节，不要求命令行或远端账号。具体客户端由已约定的小样固定并补按键卡。

核心成果：步骤及检查点、可打开文件、一次差异与恢复记录、交付检查。微练习替换部分复用练习；小样若过载，缩小语法和文件种类，保持用户要求的微练习。第 3、5 讲负荷未测；小样逐节记录耗时、提示次数和卡点，再删并节次与定课时，不能据本目录确认 90 分钟够用。

## 第 6 讲 · 综合实践：完成、核验与交付

障碍：能复现示范，换任务无法独立完成。主任务：换一组材料或领取一件真实的小任务，不新增必修术语。

| 阶段 | 具体做什么 | 检查与记录 |
|---|---|---|
| 6.1 限定任务 | 写接收者、输入材料、交付文件和完成标准；限定为能收尾的小任务 | 教师只帮助缩小范围，记录帮助程度 |
| 6.2 独立制作 | 自己选择入口、说明要求、提供并确认材料、制作成果 | 保存任务说明和中间核验，不照抄教师的成品 |
| 6.3 检查与修订 | 按风险回源、复算、打开文件；修正发现的问题 | 给可复查的依据和一处修订说明 |
| 6.4 交付与迁移 | 向实际使用者展示成果与未知；回答“换材料哪些步骤要重做” | 使用者判断是否可用；迁移和独立程度通过实际操作验证 |

## 选修：按主题设计，最多 4 讲

下列四个主题仍为候选，每次工作坊选择一个主任务，完成一件独立作品；具体选题、工具与课时在对应样章中落实。

| 主题 | 核心后深入的学习对象 | 一个可选主练习及检查 |
|---|---|---|
| 图像与声音 | OCR、ASR 或图像生成／编辑中的一条路径 | 扫描页→带出处 FAQ、录音→纪要、需求→视觉作品三选一；对图、回听或核对图中文字 |
| 表格与数据 | 表头、数据类型、缺失、去重、公式、统计图 | 清理虚构报名表，核算总数，给清理记录和一张有单位的图 |
| 个人资料与知识库 | 索引、版本、检索、分块、来源定位；RAG 解释为先检索再生成 | 小资料集问答，包含无答案题与版本冲突题；答案回到原材料 |
| Agent 与自动化 | 已跑通的流程、工具调用、权限、日志、失败恢复；API/MCP 按连接需求解释 | 把一个成熟任务做成带检查点的流程，制造可恢复失败再重试；不要求同时学配置、编程和完整 Git |

token 与上下文容量纳入核心机制；模型和工具选择用一个相同任务做对照，依据正确性、工具需求、耗时和可用条件判断。具体型号、价格与额度在任务卡按核验日期维护，不另增核心课或第五门选修。完整格式语法、编程、API/MCP 配置不设为全体先修。

## 三种载体如何对应

同一讲使用同一组目标、材料、练习与验收标准，分别适配三种使用方式：

- **Lecture 讲义**：可独立阅读的中文讲义，含案例、操作解释、失败示例、练习、答案说明和来源。暂按一讲一份，最终汇编为全课程讲义。
- **PPTX**：供教师带工作坊，包含活动指令、演示步骤、计时提示、检查表、互评问题、失败对照、练习答案与讲者备注。学生领取的材料可离线使用，现场服务失败时有演示备选。
- **交互网站**：把课堂活动转成可独立完成的自学任务，提供材料下载、操作指令、成果检查、提示与重试，例如改写任务说明、补齐材料、定位无依据主张、排序步骤。开放成果用检查表和示例反馈，机器检查只覆盖可判定项；固定示例练习之后仍有实际 AI 操作任务。

网站建议默认用固定示例和本地练习，无需登录或付费即可走完主线；真实 AI 操作通过学习者自己的可用产品完成。是否增加网站内实时 AI 练习，后续依据预算、账号条件与隐私要求决定。
