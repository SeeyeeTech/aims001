# 第 6 讲 · 大作业负例

三条正向约束对应九条负例，分别落实为结构闸、字面闸或人工清单。

| 编号 | 负例 | 形态 |
|---|---|---|
| A1 | 只有“用 AI 做一个项目”，没有材料与交付 | 脚本：任务、材料、交付章节 |
| A2 | 作业没有对应前五讲 | 脚本：1—5 的知识对应表 |
| A3 | 任务卡超长，混入完整讲义 | 脚本：1800 字符上限 |
| A4 | 只需一次提示便能交付 | 脚本：PATTERNS；清单：实质协作与反馈 |
| A5 | 没有来源、版本或未知，生成结果冒充原件 | 清单：材料和引用 |
| A6 | 把完成网页等同于理解知识 | 清单：解释、对照与迁移 |
| A7 | 没有变更资料检验，旧数据无法更新 | 脚本：验收中须有变更及验证 |
| A8 | 强制购买云服务器或完成系统工程 | 脚本：PATTERNS；清单：资源与远程边界 |
| A9 | 未试教就声称教学效果通过 | 脚本：PATTERNS；清单：实效证据 |

## PATTERNS

```PATTERNS
只需一次提示	退化为一次生成任务
必须(?:购买|租用).*?(?:云服务器|云主机)	强制付费资源
必须(?:训练模型|自建向量数据库)	超出应用先导课范围
已通过试教|已验证学习效果	未有证据的教学效果宣称
```

## CHECKLIST

```CHECKLIST
混合材料是否足够小，原件、提取结果、事实与推断是否分开
AI 协作是否有取材、核验、修改和依据，次数不是唯一达成标准
网页、数据、命令与远程环节是否使用已验证课堂入口，能否按学员条件完成
变更是否会影响真实结论，是否能检验更新而非只改页面样式
是否同时验收成果与知识解释，课时和教学有效性是否保留试教边界
```
