# 第 6 讲 · 从项目资料到可用成果

状态：大作业设计草案，材料包与工具模板待制作；尚未试教。章节范围见 [大纲](../outline.md)，判据见 [standard.md](standard.md)。

## 任务

为一个虚构项目组，把散乱资料做成可核验的执行简报与交互资料页。回答“当前要求是什么、下一步怎么做、还有什么无法确定”，让别人能沿引用查回原件。

## 材料

教师提供短小的 Markdown 要求、docx 纪要、扫描 PDF、图片、音频／视频片段，以及外部网页或课堂 API 数据。包含一处新旧冲突和一项资料未提供的信息；后半程再发变更通知。原件只读，提取与转写结果注明处理方式。

## 交付

- 项目目录：原件、提取笔记与成果分开，来源索引用 JSON，任务要求用 YAML。
- 一份 Markdown 执行简报：结论、行动、依据、未知；配一个能筛选来源／版本并打开引用的 HTML 资料页，AI 辅助修改课堂模板。
- Git 差异与恢复记录、AI 关键交互、运行命令、浏览器检查及变更验证记录。

## AI 协作

1. 让 AI 澄清目标、列计划；人确定标准与分工。
2. 解析材料、组织目录与来源；按问题检索片段，再供 AI 生成。保留“问题→取材→上下文→回答→来源”记录。无检索工具时人工模拟此机制，不称已建 RAG 系统。
3. 让 AI 比对冲突、生成简报和资料页；人核对原文，区分事实与建议，给具体反馈并修订。
4. 本地运行模板，检查 URL、API 返回、Console／Network；用 Git 检查和恢复改动。远程环节使用课堂 SSH 会话或记录，解释执行机器、目录、权限与断线影响。
5. 接收变更通知，更新资料、上下文与成果，再复查引用和页面；总结哪些步骤可复用。

## 前五讲如何用到

| 讲次 | 作业中的知识与证据 |
|---|---|
| 1 | 说明模型、上下文、工具和人的分工；沿任务链定位失败 |
| 2 | 辨文件类型、提取与识别误差；读改 Markdown、JSON、YAML |
| 3 | 目录、Git、来源版本；解释本轮取材、窗口与 RAG |
| 4 | 浏览器、网页语言、URL、API、网络与状态；查看请求证据 |
| 5 | 终端、参数、依赖与环境；辨本地和远端操作 |

## 验收

同伴任选三条结论查回来源，再问一个材料未覆盖的问题；检查未知有没有被编造。加入变更后验证旧结论、数据与页面是否同步更新。

学员解释一次格式选择、一次上下文取舍和一次错误修复；分别检查事实依据、成果质量与执行证据。多轮交互须留下判断与修订理由，轮数和漂亮页面不能单独证明学会。

## 开课前

教师准备虚构材料、预置筛选／引用／启动功能的页面模板、课堂 API 和远程演示记录，并实际走查入口；提供提取稿、转写稿与静态 API 返回备用，区分模拟和实测。AI 协助制作与检查。第一轮小样决定材料量、操作范围和课时。
